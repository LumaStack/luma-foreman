# Nobody has a format for knowledge that is not a procedure

**`SKILL.md` answers *how do I do X*.** A glossary, an architecture
description, a standing rule and a record answer nothing of the kind, and they
have no home in the ecosystem except as attachments subordinate to some skill.

**That is the actual gap**, and it is the one thing in this space that is not
already solved by somebody else.

## Why it matters here

**Foreman's whole premise rests on it.** Everything it carries that is *not* a
workflow — policy, concepts, types, records — is exactly the class with no
standard. If skills were sufficient, adoption would be a plugin manager and
foreman would not need to exist.

**It also explains the shape of `apply`.** Workflows project cleanly, as skills.
Everything else has to arrive by a mechanism foreman invented — an entry point,
rings, `matches` — because there was nothing to conform to.

## This belongs upstream

**Its home is `luma-knowledge-format`, not foreman.** The observation is about
what a knowledge format is for, and LKF is the answer to it; the spec states
neither the gap nor that it is the thing being answered.

Filed here because it was found here and there is nowhere else to put it —
the same reason [[routers]] gives. **If it lands in the spec it should move.**
