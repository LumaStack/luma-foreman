# Clear between jobs

When you finish one job and start a different one, run `/clear`.
If you do **only one thing, this will have the largest impact** — by a landslide.

Staying in the same thread because it is convenient will get very expensive.
The previously finished conversations are not sitting quietly out of the way — they are being resent on every
turn until the session ends. A session sitting at 80,000 tokens of history
drops to nothing the moment you clear.

**Rename before you clear.** Make it a muscle memory. Run `/rename` before `/clear`, and
`/resume` can find it again by name if you need. You are not throwing the work away.
You are stopping the next job from carrying it.

**Do not clear in this tutorial.** Clearing is how this tutorial ends — it is the last thing
you will be asked to do — and doing it now would reset the tutorial. If
you want to try these lessons immediately, open a second window and try there.

## Takeaways

- Finished one job and starting another? **`/clear`.**
- An old conversation isn't sitting quietly; it is resent on every message until the session ends.
- **`/rename` before `/clear`**, so `/resume` can find it if you were wrong.
- Running `/clear` as a habit is going to cut token usage far more than any other strategy in this tutorial
