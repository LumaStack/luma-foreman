# README template

Copy the block below to `README.md` and fill it in. **Copy the block, not this
file.** Guidance is in `../policy/readme.md`.

Four sections is the default shape. Delete a heading rather than leaving it
empty, and add one only when it earns its place.

```markdown
# <name>

<One or two sentences. What it does for somebody, not what it is built from.
This is the only part guaranteed to be read — a reader decides here whether to
continue.>

> **Status:** <only if it affects adoption — unstable, unmaintained,
> experimental, pre-release. Delete this line otherwise.>

## Why it exists

<The problem it solves, or what was wrong with the alternatives. The section
most often skipped and the one that most often decides adoption: anyone can see
what from the code, and nobody can reconstruct why.>

## Example

<Optional — some projects are clearer without one. If included, make it the
smallest thing that actually works, and make sure it runs.>

## <Next steps>

<Short links with a reason to click, not an inventory.>

- [Getting started](docs/getting-started.md) — <why you would>
- [Contributing](CONTRIBUTING.md) — <why you would>

## License

<Name it and link it.>
```

## Before you commit it

- **Read it as somebody who has never heard of this.** No context: not the
  domain, not the tooling, not the team's vocabulary.
- **Run the example.** An example that does not work is worse than none, because
  it costs the reader their first ten minutes and their trust.
- **Check what you were tempted to add.** API reference, version history,
  development setup, architecture, roadmap — each has a home in
  `../policy/which-document.md`. Every one of them pushes the four sections that
  matter further down.
